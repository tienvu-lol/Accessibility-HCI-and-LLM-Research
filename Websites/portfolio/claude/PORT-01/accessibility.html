Accessibility

This site was built as a WCAG 2.2 AA baseline for accessibility and usability research. Here is what that means in practice, and where it stops.

Conformance target

WCAG 2.2 Level AA. The site is a research replica, so this is a stated target supported by automated checks, not a formal conformance claim.

What is built in

  • A skip link, and landmarks on every page: header, two labelled nav regions, main, aside where there is a sidebar, and footer.
  • One h1 per page and a heading order that never skips a level.
  • A visible 3px focus indicator, offset outside the component, in a blue reserved for focus and used for nothing else.
  • scroll-padding-top so the sticky navigation never covers the element that has just received focus (2.4.11).
  • Interactive targets of at least 24×24 CSS pixels; most are 44px (2.5.8).
  • Form fields with visible labels, autocomplete tokens (1.3.5), inline errors linked by aria-describedby with aria-invalid, and an error summary that takes focus (3.3.1, 3.3.3).
  • Filter and search result counts announced through polite live regions (4.1.3).
  • Status conveyed with text as well as colour (1.4.1).
  • Scroll-reveal animation and smooth scrolling disabled under prefers-reduced-motion (2.3.3).
  • No horizontal scrolling at 320px (1.4.10), and a layout that holds at 400% zoom.
  • Help in the same place on every page: the email address and copy button in the utility bar (3.2.6).

Known limits

  • No manual screen reader testing has been recorded for this replica (NVDA, JAWS, VoiceOver).
  • Decorative canvas and SVG placeholders carry no information and are hidden from assistive technology.
  • External links open in the same tab and are marked with an arrow and visually hidden text; some destinations are platform home pages, not real profiles.

Telling me about a problem
