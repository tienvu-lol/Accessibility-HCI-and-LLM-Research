Accessibility

A motion studio's site is the obvious place to get this wrong, so here is exactly what this one does.

Conformance target

WCAG 2.2 Level AA, supported by automated checks in both the light and the dark palette. This is a stated target for a research replica, not a formal conformance claim.

Motion, specifically

  • No animation plays automatically for anyone whose system asks for reduced motion: the looping pieces are stopped in CSS, not merely paused.
  • A single Motion control sits in the header on every page and stops every loop at once (2.2.2). It reports its state with aria-pressed and announces the change politely.
  • The project slideshow never starts on its own, pauses on hover and on focus, and can be driven with the arrow keys.
  • Looping marks are decorative, aria-hidden, and carry no information that is not also in text.
  • Nothing flashes; no element changes more than twice a second (2.3.1).

The rest of the baseline

  • A skip link, and landmarks on every page: header, a labelled nav, main, aside where there is a sidebar, and footer.
  • One h1 per page and no skipped heading levels.
  • A 3px focus indicator offset outside the component, in a colour reserved for focus.
  • Targets of at least 24×24 CSS pixels; most are 44px (2.5.8).
  • Forms with visible labels, autocomplete tokens (1.3.5), inline errors linked by aria-describedby with aria-invalid, and an error summary that takes focus (3.3.1, 3.3.3).
  • Filter, view, slideshow and estimator changes announced through polite live regions (4.1.3).
  • Status conveyed in text as well as colour (1.4.1); external links say so in visually hidden text.
  • No horizontal scrolling at 320px, and a layout that holds at 400% zoom.

Known limits

  • No manual screen reader testing is recorded for this replica.
  • The showreel is a demo player: no video file is bundled, so there are no captions or audio description to evaluate. A real deployment would need both.
  • Outbound links point at platform home pages rather than real profiles, because the studio is fictional.

Reporting a problem

Email studio@junosalvi.example. In a real deployment that address would be monitored and this statement would carry a review date.
