Transit Clock

A departures board for a hallway screen, legible at four metres, that announces changes politely instead of flashing them.

  • Web Components
  • SVG
  • ARIA live

What it is

A departures board for a shared hallway screen.

The problem

The building had a screen showing a transit app at 80% zoom, unreadable from more than a metre and flashing whenever anything changed. I wanted a board you could read while walking past, that announced changes without demanding attention.

How I built it

  • Type sized for a four-metre reading distance, which turned out to mean far fewer rows than anyone wanted.
  • Changes land in a polite live region and fade in; nothing blinks, nothing moves on a timer.
  • Each row is a small custom element with its own accessible name, so the same markup works on a phone.
  • Demo data is bundled, so the board runs with no network at all.

What it looks like

Three placeholder images. On a real case study these would be screenshots and a short screen recording.

Where it got to

  • Two hallway screens, nine stations, no complaints about flashing.
  • Readable at four metres and at 400% browser zoom, which are nearly the same problem.
  • The polite-announcement pattern was copied into two products at work.

What I would do differently

Reading distance is a layout constraint

It cut the row count from twelve to five and made every later decision easier.

Polite beats assertive, almost always

An assertive live region on a departures board is a machine shouting at a corridor.

Bundle the demo data

The board survived three network outages because it never needed the network to render.
