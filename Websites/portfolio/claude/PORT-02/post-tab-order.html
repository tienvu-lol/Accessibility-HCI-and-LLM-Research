Tab order is a product decision

September 30, 2026 8 min read by Priya Raman accessibility · process

Every team I have worked on has a design review, a code review and a QA pass. None of them has ever had a line item for tab order. So it gets decided by accident: whatever order someone happened to write the elements in, plus whatever CSS later moved around on screen without moving in the DOM.

Why it is a product decision

Tab order is the order in which your product explains itself to anyone who is not using a mouse. That includes screen reader users, people with tremor or RSI, anyone on a laptop with a broken trackpad, and the power users who are the loudest advocates you have. The sequence is a statement about what matters first. That is a product decision wearing an engineering costume.

The giveaway is what happens when you fix one. On our scheduling view, moving the filter bar ahead of the results table in the DOM cut the number of keystrokes to a common task from 23 to 6. Nobody had specified 23. Nobody had specified anything.

How we made it reviewable

  • Every new screen ships with a numbered keyboard path in the pull request description: the actions in order, the keystroke count for the top three tasks.
  • A Playwright test walks the page with Tab and records the sequence. A diff in that sequence fails review until someone explains it.
  • CSS that reorders visually — grid placement, flex order, absolute positioning — needs a comment saying why the DOM order still matches.
  • No positive tabindex. Ever. There is no legitimate case in our codebase and allowing one invites fifty.
“A number in a pull request ends an argument that a strong opinion cannot.”

What it costs

About fifteen minutes per screen, and a willingness to rewrite your markup when the easy CSS answer would break the sequence. That is the whole cost. It is cheaper than any of the three audits we commissioned before we started doing it, and the audits only told us what we already knew by then.

If you want a place to start: take your busiest screen, unplug the mouse, and do the main task. Count the keystrokes. Write the number down. That number is now a product metric.
