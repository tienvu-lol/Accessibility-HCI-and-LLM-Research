Approvals and environments enforce who can deploy where.

How it works

  1. Commit. A push or merge request starts the pipeline.
  2. Build and test. Jobs run in parallel on shared or self-hosted runners.
  3. Scan. Security checks add findings to the review.
  4. Deploy. Approved changes move through environments.

CI/CD questions

Yes. Runners can be shared, dedicated or self-hosted.

Path-based rules and merge trains keep unrelated changes from blocking each other.
