## Interaction and simulation notes

- Nothing is transmitted. Every form ends in a "Demo only" success message that says nothing was sent. No account, payment, delivery change or email exists.
- Weather, markets, scores, "Most popular", "Trending", the e-edition and events are static sample data, labeled as such on screen.
- Share: Copy link uses the browser Clipboard API (may be refused on `file://`; a status message says so); Email builds a `mailto:` link; Print calls `window.print()`.
- Search and article pages read the query string. `article.html?id=s1` ... `s34` render from inline data; an unknown id shows a "Story not found" state.
- `js/main.js` begins with the data, then shared HTML templates, then behavior. The static HTML in the pages was generated from the same templates by a throwaway local script that is not part of the delivery; the delivered site needs no build.

## Known limitations

- Copy/clipboard may fail on `file://`; a message explains.
- The reference's multi-level mega menu (about 40 links) is reduced to the main section and topic links; "Marijuana", "BestReviews", "En Español", archives and the store are omitted.
- Article images are SVG placeholders, not photographs.
- Search is substring matching over 34 stories (no stemming, no typo tolerance).
- Several sub-menu topics lead to filtered lists with a single story or an empty state by design.
