- **Machines are ambiguous.** The `Machines` legend showed the one live Windows worker (`100.112.79.22`) plus historical generic IDs `laptop-arc`, `laptop-arc-a5`, `laptop-arc-a6`, and `worker`, without explicit offline labels. `tailscale status` separately showed the Mac `samhiths-macbook-air` active, but `/api/state` listed no Mac launcher or worker and the GUI didn't explain this distinction. - **No per-job stop.** `Unclaim` only clears the not-yet-picked-up batch allowance. `Pause` stops new claims, not running jobs. The bottom `Docker workers → Remove` controls only cover host-managed containers and can interrupt every job on a container. None is a stop control for one running job.

## Fix in this order

1. **Make the Job queue the place to dispatch.** Show queued jobs or arm groups with a machine picker and explicit `Claim A1`/`Deploy & claim A1` (same for every configured arm). Use a stable job ID or explicit arm/phase filter end to end, from API to launcher intent to the eventual worker lease. Revalidate eligibility on the server: supported job kinds, live tunnel for ARC repair, slots, caps, paused state and budget. Do not dispatch unrelated jobs. Show why no A1 work is available in the selected scope and why a machine cannot take a given job. Keep queue and launcher states visible independent of running containers. Handle simultaneous operators; one job must not be reserved by two workers.
2. **Separate presence from history.** Show one machine row per actual device, with subrows or badges for individual workers/arms and separate labels for Tailscale presence (only if backed by actual Tailscale data), launcher online, and worker online. Identity shown today is agent-reported. Do not infer that legacy IDs belong to the Mac, or infer that a visible peer can deploy Docker. Move historic machine IDs to attribution/history or label them explicitly. Use a shared online timeout/freshness rule for launcher/worker status where appropriate; the machine view and worker rows currently use different worker cutoffs. Test both machines with two browser sessions and realistic check-ins, including the worker container going away while its launcher stays up.
3. **Add scoped unassign and stop.** Pending reservations/deployments need a clear cancel control; running jobs need a separate **Stop job** action. Decide whether stopped work is requeued or stays canceled and show it clearly. Signal the owning worker to abort only that job; don't remove the Docker container or stop other work. Bind lease mutations to worker + lease generation so a late heartbeat/result/release cannot overwrite a stopped or re-leased job. Confirm a stop in the UI only when the worker acknowledges it or the lease expires. Calls already sent to a provider may still be billable.
4. **Verify in Playwright, not just unit tests.** Use temporary test volumes and mock providers with fixtures for queued A1, queued A7, an already-running job, two machines, and a zero-worker view. Assert: queue visible with zero workers; select A1 and host B and only that job starts on B; host A cannot claim unavailable ARC work; last-second competing claims won't double-run; unassign pending and stop one active job without touching another; status and controls sync in both browser sessions without refresh. Check keyboard focus and an in-progress cap edit across SSE updates. Pair these with unit/API regression tests. Only then smoke-test the real Tailscale URL without starting a paid run.
