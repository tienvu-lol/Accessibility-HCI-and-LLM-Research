Build:
1. worker.js (zero-dep Node 24): POST /api/worker/claim (Bearer WORKER_TOKEN; kinds repair/judge/score; up to WORKER_SLOTS concurrent), heartbeat every 60s per running job, on ANY infra failure (network, spawn, scratch dir, base prep) call /api/worker/release {retryable:true} IMMEDIATELY so the lease is not held (hackloop's biggest defect was exactly this), on completion POST /api/worker/result; exponential backoff on server errors; graceful SIGTERM (release running jobs); never log api keys; keys reach subprocesses via env only (name = job.api_key_env), never argv or files. Jitter claim polling so replicas do not stampede.
2. lib/runjob.js. runRepair(job): scratch root (copy Study/{prompts,criteria,sample,baseline,tools,config} from the image; config copied then the arm's provider/base_url/model_id/model_version overridden from the job; mock:true sets STUDY_MOCK=1), run `python Study/tools/runner/runner.py --arms A --conditions C --sites S --root <scratch> --max-iter N` (PYTHON env or python3/python), collect scratch/runs/<arm>/<cond>/<site>/** into a files map under runs/..., sum usage and calls from status.json; ok if the cell reached a terminal iteration, else failed with the reason from status.json. runScore(job): materialize each iteration (or baseline) to a temp dir, run `node Study/tools/score/score.js` (--rules-out per iteration, rows to a temp CSV; another agent is adding --category/--generator-group/--rules-out: if --rules-out is unsupported, still return rows and empty rules), return rows + rules. runJudge(job): worker/judge_job.py imports Study/tools/judge blind.build_item + judge.judge_item with a complete_fn wrapper capturing usage and using providers.complete with the job's gemini config (OpenAI-compatible base_url; mock => judge's mock), writes a temp runs tree from job.variants, prints rows (judge_rankings), key_rows (blinding_key), usage, call_id as JSON on stdout.
3. worker/estimate.py (stdlib): `--study <dir> --out <file>`: per site x condition estimated input tokens (len(runner.build_prompt(...))/4) and output tokens (slice html+css chars/4*1.1), per-arm call-count upper bound; JSON {site:{condition:{in,out}}, mean_in, mean_out}.
4. Dockerfile.web (node:24-bookworm-slim + python3; copies Study/webapp plus the Study files the server and estimate need: sample, config, prompts, criteria, baseline, tools, metrics seed, human rubric; non-root; VOLUME /data; DATA_DIR=/data; HEALTHCHECK /healthz). Dockerfile.worker (Playwright base image matching the playwright version in Study/package.json + node 24 + python3; npm ci inside Study; non-root). DEPLOY.md: step-by-step Railway setup (two services from this repo, Root Directory Study, config file paths, web volume at /data, env vars from the contract, WORKER_TOKEN generation, private networking WEB_URL=http://<web-service>.railway.internal:8080 vs public URL, scaling replicas and WORKER_SLOTS, per-arm concurrency math, cost warning, importing open-source runs from ARC with pack_runs.py). worker/pack_runs.py: `--runs Study/runs --arms A5,A6 --out runs.ndjson.gz` producing exactly the import NDJSON format ({"cell":"A5/wcag/UNI-01","files":{"iter1/index.html":{"enc":"utf8","data":"..."}}}) and optionally `--post URL --token T`.
